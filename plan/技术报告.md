# 技术报告：专利年费与费减合规计算工作台

> 项目：patfee —— 官方费率表规则化 · 年费阶梯与滞纳金 · 费减资格判定 · 专利组合批量排期对账 · 证据链留痕
> 版本：v0.1.0（M5 里程碑，2026-10-14）
> 形态：Windows 桌面应用（PySide6 + PyInstaller onedir exe）+ CLI 双入口，全本地处理、零上传、零 API 依赖

---

## 一、问题与定位

专利年费缴纳是"政策数值 + 日历规则 + 主体资格"三重耦合的合规计算：

1. **年费阶梯**：三类专利各自独立的多档年费表，金额随缴费年度跳档，恰好跳档年归新档；
2. **滞纳金**：逾期后按月累加（5%/月）、6 个月补缴上限、自然月口径；
3. **费减判定**：主体收入/应纳税所得额阈值（严格小于）、共同主体比例差异、多政策择一不叠加、政策版本按年度锚点切换（78 号 → 316 号 → 594 号）；
4. **组合管理**：整组合跨年度排期、到期预警、两轮台账对账。

通用工具（表格、提醒类小工具）不具备"逐项挂政策依据、版本可切换、结论可溯源"的能力；LLM 聊天给不了持久费率表与可复现的批量对账。patfee 把这条链做成**费率表规则化、逐项挂政策依据、可批量排期**的本地计算工作台——定位是专利费用管理与申报减缴前的**口径防线**。

## 二、费率表规则化方法

### 2.1 数据分层

规则不进代码，进**版本化规则包**（`data/rules/`）：

| 层 | 内容 | 生成者 | 纪律 |
|---|---|---|---|
| 规则包 | 费率表（fee_schedule）+ 三代费减阈值（reduction_78/316/594） | `tools/gen_rulesets.py` | 冻结产物禁手改；`--check` 再生成逐字节一致 |
| 依据索引 | 上位法文书定位（《专利法》《实施细则》《审查指南》） | 抓取脚本 + 手工登记 | 8 份原文快照 sha256 入台账 |
| 合成真值 | 18 件虚构专利 + 46 条算例 + 误报对照集 | `tools/gen_synthetic.py` | 零真实信息；自研 splitmix64 确定性 RNG |

每条规则条目携带 `status`（verified / pending / input_required）与 `basis`（文号、条款、URL、抓取日期、复核结论）——**门控**在引擎入口：`pending` 条目被拒进计算（exit 1，`--preview` 可预览但退出码仍为 1）。"值可用"与"值已核对"是两个独立的闸门。

### 2.2 零政策字面量门禁

"规则值只能来自规则包"由静态扫描强制：`src/patfee/**/*.py` 与 `tools/` 报告脚本全量扫描禁用数值 token（费率、阈值、比例——即规则包中出现的全部政策数值），命中即构建失败；日历常数（|n|<100）与精度常数（0.01 等）显式豁免并镜像登记进 manifest 两处守一致。门禁自身可证伪：阳性对照注入一个禁用 token 必须报红，token 集为空按配置错误处理。

M5 起新增文件的实测：GUI 占位文本里写了个政策数值（月收入阈值 5000），门禁立即拦截——证明该防线对新增源码（含 docstring 与注释）持续生效。

### 2.3 逐项复核流程

32 条规则逐条回官方来源核对后置 `verified`：15 档阶梯端点+金额、8 项费率、滞纳金 5% 逐档解码费率表页；费减阈值逐条回政策原文（78 号第四条/第十二条、316 号第一条、594 号第一/二条）；《实施细则》第 5 条（自然月）与第 115 条（6 个月补缴期）落滞纳金口径。复核痕迹全部写入 `basis.note`。

## 三、计算引擎设计

### 3.1 年费阶梯

档位查找用 `from_year/to_year` 双闭区间显式表达，"恰好跳档年归新档"由基准枚举锁定（B1 套件从规则表推导端点全枚举：区间连续性、逐年唯一命中、边界归属三断言）。引擎不写任何费率数字——金额、区间、档位标签全部来自规则包条目。

### 3.2 滞纳金

逐月累加（费率条目驱动，不写死 5%）、上限月数读 `late.grace_months` 条目、自然月口径读 `late.month_basis` 条目。超上限是 **warning 不是 fail**（风险提示 ≠ 法律判定），退出码降级为 1。

### 3.3 费减判定

三个关键口径：

- **严格小于**：收入/所得恰好等于阈值即不合格（有边界算例锁定）；
- **多政策择一不叠加**：开放许可与费减并存时取最优惠候选，`no_double_benefit` 显式输出；
- **年度锚点**：按缴费年度选 316 号前后的阈值集，锚点信息随结论输出。

### 3.4 编排上收（D26）

全部业务判断上收为 `calc/pipeline.py` 公开函数组（build_* → compute_full_* → *_lines → *_exit_code_for），CLI 与 GUI 共用。"同一个业务判断在项目里只有一处实现"由**三方对账测试**守门：CLI stdout = 编排直调 = 报告章节（scan 通路三方、calc/reduction 两方，逐行相等断言）。

### 3.5 组合排期与对账

失败件隔离（坏格式单列 `failed`，不中断整批、不改变退出码）；退出码只由"是否检出问题"决定；到期预警按剩余天数升序、窗口可覆盖；跨轮对账三集合（新增到期/已缴清/持续未缴）配对主键 = 专利号（稳定身份键，非内容指纹，D13），内容变化另立 `content_changed`，`paid_on` 变化不误报。`today` 显式注入引擎（禁系统时钟），对账口径单一实现源在 `calc.portfolio.compare_rounds`。

## 四、基准与可证伪性

内置评测基准 `patfee bench` 四套件（B1 阶梯 99 例 / B2 滞纳金 18 例 / B3 费减 20 例 / B4 组合 48 例），三条出口纪律：

1. **门槛随 manifest 下发且实际执行**：`min_pass_rate` / `max_fail` / `max_seconds` 三项真实判定（M4 前 `max_seconds` 曾是"下发未执行"——教训：交接文档写的"已下发"≠"已生效"）；
2. **期望独立于实现**：B4 金额期望只读冻结真值库（不读现行规则包）——期望与引擎同源时注入缺陷两边一起变，探活永远绿（D50 实测教训）；
3. **每套件可证伪**：9 条探活测试注入缺陷必报未达标（阶梯空洞/重叠、费率翻倍、阈值抬高、金额篡改、controls 失效、对账漏报、计时超时×2）。

指标固化进 README（实测快照与实时判定语义分离，K46）。

## 五、桌面交付（M5）

### 5.1 GUI 零判定逻辑的三层防线（D27）

1. **AST 静态门禁三条**（`tests/test_m5_gui.py`）：① 不 import 规则层/领域层内部模块；② 无算术 `BinOp`（`* / - // % **` 全禁，`+`/`%` 仅限文本排版）；③ 无政策数值字面量（同一份 BANNED_TOKENS）。
2. **架构约定**：GUI 服务层 `gui.compute_lines` 是唯一引擎调用点，三条通路全部转发 `calc.pipeline`。
3. **行为断言**：offscreen 交互测试用桩服务验证"界面只渲染服务层返回的行"，真服务接线测试验证金额来自规则包。

### 5.2 打包

- PyInstaller 6 onedir 双 exe：GUI（console=False）+ CLI（console=True），同一 `main`；datas 由 `patfee.packaging.build_datas()` 单一事实源产生（规则包 + 真值库 + 依据索引；原文快照不入包）；
- 构建后断言：dist 全树禁区成分扫描 + 内嵌数据与仓库逐份 sha256 对账 + data/ 白名单外目录检测；
- `patfee --selftest <输出json>`：冻结态自检（数据目录落点在 exe 树内 + 规则加载 verified>0 + calc 全链路 + 基准全达标 + GUI offscreen 冒烟），退出码携带成败；
- 实测记录：CLI exe 首版构建漏传 `Analysis.scripts` 进 EXE 导致 bootloader 无入口（0.03s 静默退出）——修复后 `--selftest` 全绿。

### 5.3 报告导出（MD/XLSX 双格式）

- **单一渲染源**：`report.scan_report_sections` 返回结构化章节列表，Markdown 与 XLSX 渲染器各自消费——两格式内容一致是结构性质；
- **XLSX 逐字节可复现**：openpyxl `save` 后重打包（zip 条目 `ZIP_STORED` + 固定 `date_time=1980-01-01` + `create_system=0`；`dcterms:modified` 在 save 阶段被 openpyxl 用当前时刻重打戳，重打包阶段统一替换为固定值）——跨进程两次导出 sha256 一致实测背书；
- **纪律延续**（K42）：未启用章节显式写出（"没查"≠"查了没问题"）；无外链——Markdown 正文无 URL，XLSX 无超链接对象与外部关系项（OOXML xmlns 规范 URI 是格式固定成分，不是外链）。

## 六、质量保障体系

| 维度 | 机制 |
|---|---|
| 确定性（NFR-1） | 冻结产物无时间戳无 CR；生成器 `--check` 位级一致；XLSX 重打包可复现 |
| 计价精度（NFR-2） | 全链路 Decimal、两位小数 ROUND_HALF_UP、`parse_float=Decimal`、拒绝浮点直传 |
| 零上传（NFR-3/4） | 无 HTTP 客户端调用；报告无外链；GUI `openExternalLinks(False)` |
| 分层纪律（NFR-5） | 核心层零第三方依赖（重件 extras + 惰性导入，try 包住"import 到调用完成"整段） |
| 退出码语义 | 四态（0/1/2/3）锁进测试；`--preview` 永远 exit 1 |
| 回归 | 160 项测试三解释器（py3.8/py3.12/干净 venv）全绿、收集数一致 |
| 编码守卫 | 所有控制台入口 `ensure_utf8_stdio()` 探针式改写 |

## 七、决策与教训（对后续同类项目可复用）

1. **期望与实现必须异源**（D48/D50）：基准期望读冻结真值，不读引擎正在读的同一份规则包——否则"注入缺陷两边一起变，探活永远绿"。
2. **"已下发"≠"已生效"**（M4）：`max_seconds` 门槛写了 manifest 却没人执行，接手时先验证声明与代码的差距。
3. **门禁写进占位文本也会拦**（M5）：GUI demo 文案里的政策数值被零字面量门禁拦截——防线对"非计算代码"同样生效，这正是扫描面含 docstring/注释的价值。
4. **PyInstaller 入口必须显式传 `Analysis.scripts`**（M5 实测）：EXE 只接 PYZ/数据时 bootloader 无入口，0.03 秒静默退出码 0。
5. **openpyxl 的 `modified` 戳不尊重属性赋值**（M5 实测）：`Workbook.properties.modified` 赋固定值后 save 仍写当前时刻，需在产物层替换。
6. **数据目录落点必须有运行时断言**：`data_dir_within_exe()` 在冻结态自检里验证"数据随包走"，防"本地能跑、换机即废"。

## 八、结论

M5 出口判据逐项达成：GUI AST 门禁三条齐上（测试锁定）；exe `--selftest` 冻结态断言通过（六项检查全绿、退出码 0）；三方对账测试落地（CLI stdout = 编排直调 = 报告章节）。XLSX 双格式逐字节可复现、技术报告（本文）同步交付。项目具备进入 M6（脱敏发布 GitHub + Release）的条件。
