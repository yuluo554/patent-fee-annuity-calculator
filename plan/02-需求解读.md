# 02 需求解读（痛点 → 能力转译 · FR/NFR · 边界守卫）

> 上游：[01-题目详细定义.md](01-题目详细定义.md)。本文把题目要求转译为**可实现的编号需求（FR/NFR）**，每条挂验收方式与所属里程碑；「边界与非目标」一节的守卫项无对应 FR 者一律不实现。

## 一、读者与使用场景

| 读者 | 场景 | 需要本工具给出的东西 |
|---|---|---|
| 企业知识产权/费用管理员 | 一个组合数十上百件，跨年排期、逐件确认应缴额 | 逐件年费金额 + 所处阶梯区间 + 政策依据 + 未来 N 个月到期清单 |
| 代理机构费用岗 | 代客户核算并说明"这笔钱怎么来的" | 逐项挂费率表项目与政策文号的确定性输出 + 可导出报告 |
| 申报费减的申请人 | 判断够不够格申请减缴、减多少 | 资格判定（阈值）+ 减缴比例 + 减免后应缴额 |
| 内部/客户/存档 | 复盘与留证 | 报告（MD/XLSX）+ 组合与结果 sha256 指纹 |

## 二、痛点 → 能力转译表

| # | 痛点（题目 §一） | 能力 | 关键设计约束 |
|---|---|---|---|
| P1 | **阶梯易错**：年费按年度区间跳档，人工算错即误缴/漏缴 | 年费阶梯计算引擎（FR-1） | 金额只由 Decimal 产生；阶梯档边界显式处理并在基准中枚举 |
| P2 | **滞纳金按月累加**口径不统一 | 滞纳金与恢复权利计算器（FR-2） | 费率与宽限期**由规则包承载**，不硬编码 |
| P3 | **费减比例口径混淆**（"个人 85%/企业 70%"是错的） | 费减资格判定与减免额（FR-3） | 比例取决于**主体是否共同**；阈值按**年度锚定**（316 号前后不同） |
| P4 | 同时能享多项减免时不知怎么选 | 多政策择一判定（FR-3.3） | 择最优惠、不得重复享受，判定过程留痕 |
| P5 | **组合难管**：跨年度排期与"哪件快到期"靠台账盯 | 组合批量排期与对账（FR-4） | 失败件隔离不中断；跨轮对账三集合 |
| P6 | 政策口径逐年变化，历史年度回算容易被"新阈值重算旧年度" | 版本化费率与政策规则集（FR-5） | `依据文件 × 版本`；按年度锚定；`status` 门控 |
| P7 | **依据无据**：要向内部/客户说明算法与出处 | 证据链与报告导出（FR-6） | 报告含**参数来源块**；逐项挂文号/费率表项目；指纹固化 |

## 三、功能需求（FR）

优先级：**P0** = 首期必需（否则不成立）；**P1** = 评分主要得分面；**P2** = 加分/扩展。

### FR-1 年费阶梯计算引擎（P0，M1 数据 + M2 引擎）

| 编号 | 需求 | 验收方式 |
|---|---|---|
| FR-1.1 | 输入专利类型（发明/实用新型/外观设计/外观设计国际注册）、申请日/授权日、缴费年度，输出当年应缴年费 | CLI `calc` 单件算例 |
| FR-1.2 | 三类专利**各自独立阶梯**，按年度区间确定性取档 | 阶梯边界基准（B1） |
| FR-1.3 | 输出**金额 + 所处区间 + 政策依据**（费率表项目 + 政策文号） | 结果结构含 `basis[]`，报告逐项渲染 |
| FR-1.4 | 金额**仅由 Decimal 运算产生**，禁止浮点直算 | 静态扫描：核心层无 float 字面量参与计价；`parse_float=Decimal` |
| FR-1.5 | 年度区间**边界显式处理**（如第 3 年与第 4 年之间跳档）并在基准中枚举 | 边界枚举断言（档内首末年度、恰好跳档年） |
| FR-1.6 | 年度基准计算：由申请日推导当前年度（缴费年度 = 申请日起算年度） | 日期算例（含闰年、跨年） |

### FR-2 滞纳金与恢复权利计算器（P0，M2）

| 编号 | 需求 | 验收方式 |
|---|---|---|
| FR-2.1 | 逾期缴费按"每超过规定缴费时间 1 个月，加收当年全额年费的 5%"确定性计算 | 滞纳金基准（B2） |
| FR-2.2 | 支持**跨月累加** | 逾期 1/2/6 月算例 |
| FR-2.3 | 恢复权利请求费、专利权评价报告请求费等按费率表计入 | 费目算例 |
| FR-2.4 | **宽限期/上限规则由规则包承载**（哪个时点后进入失效流程），不硬编码 | 规则包字段存在且门控生效；改规则包即改行为 |

### FR-3 费减资格判定与减免额计算（P0，M2）

| 编号 | 需求 | 验收方式 |
|---|---|---|
| FR-3.1 | 输入主体构成（个人/单位/共同主体数）、上年度月均收入或应纳税所得额、年度 | CLI `reduction` 单件算例 |
| FR-3.2 | 按**公告第 316 号调整后的阈值**判定资格（个人年收入低于 6 万元 / 企业应纳税所得额低于 100 万元），阈值随年度锚定 | 边界主体枚举（恰好等于阈值 = 不满足） |
| FR-3.3 | 输出**适用减缴比例**：单主体 85% / 共同主体 70%（依财税〔2016〕78 号第四条原文） | 共同主体数 1 与 2 的对照算例 |
| FR-3.4 | **多政策择一与不得重复享受**显式判定并留痕（公告第 594 号） | 算例：开放许可减免 15% 与费减 85% 并存 → 择最优惠 |
| FR-3.5 | 开放许可年费减免 15%、补偿期年费 8000 元/年、期限补偿请求费 200 元/件按规则包计入 | 专项算例 |

### FR-4 专利组合批量排期与对账（P1，M3）

| 编号 | 需求 | 验收方式 |
|---|---|---|
| FR-4.1 | 批量读入**多主体 × 多专利 × 多年度**台账（清单/目录） | `scan` 命令跑合成组合 |
| FR-4.2 | **失败件隔离不中断**：坏格式/缺字段/类型不识别 → 单列原因码，整批继续 | 混入坏件算例，断言退出码不含"失败件"语义 |
| FR-4.3 | **跨轮对账**输出"新增到期 / 已缴清 / 持续未缴"三集合 | 两轮 baseline 对账算例 |
| FR-4.4 | **优先级排序**：按距最近缴费期限升序输出"未来 N 个月内到期清单" | 排序断言 |
| FR-4.5 | 对账**配对主键 = 稳定身份键**（专利号），非内容指纹；内容变化另立 `content_changed` 标记 | 对账算例：金额变 → 仍配得上 |

### FR-5 版本化费率与政策规则集（P0，M1）

| 编号 | 需求 | 验收方式 |
|---|---|---|
| FR-5.1 | 规则包按 `依据文件 × 版本` 组织，各成独立规则集，挂 `doc_no`/条款/URL/抓取日期 | 规则包 schema 校验测试 |
| FR-5.2 | **政策差异报告**：一键列出 316 号调整前后的阈值差异与 594 号新增项目/减免 | `rules diff` 命令输出 |
| FR-5.3 | **按年度锚定规则版本**（2019-07-01 前后、2024-08-06 前后分别适用），杜绝"用新阈值重算旧年度" | 跨锚点年度算例（同一输入不同年度 → 不同阈值/项目） |
| FR-5.4 | 每条规则挂 `status`（`verified`/`pending`/`input_required`），**未核对不得进入计算路径** | 门控测试 + 预览不拦截但退出码非 0 |

### FR-6 证据链与报告导出（P1，M3 → M5）

| 编号 | 需求 | 验收方式 |
|---|---|---|
| FR-6.1 | 每个计算结论可挂证据（本地文件引用 + 指纹）；组合台账与结果整体计算 sha256 随底稿固化 | 报告被改动即可检出 |
| FR-6.2 | 一键导出**专利费用测算报告**（Markdown + XLSX）：组合清单 / 逐件年费排期与依据 / 费减资格与减免额 / 滞纳金与恢复权利 / 到期预警 / 规则包坐标与证据指纹 | 两格式内容对等断言 |
| FR-6.3 | 报告头固定输出**规则包坐标**（费率表版本 + 政策版本号 + 生成时间以外的确定性字段） | 报告头结构断言 |
| FR-6.4 | 报告**无外链**、断网可开；**未启用章节显式写出** | 无外链硬断言 |

### FR-7 内置评测基准（P0，M0 起逐里程碑扩张）

| 编号 | 需求 | 验收方式 |
|---|---|---|
| FR-7.1 | 阶梯边界基准：档内首末年度 + 恰好跳档年，枚举验证金额 | B1 套件 |
| FR-7.2 | 滞纳金基准：跨月累加与费率上限边界枚举 | B2 套件 |
| FR-7.3 | 费减判定基准：收入恰好 6 万 / 所得额恰好 100 万 / 共同主体数 1 与 2 | B3 套件 |
| FR-7.4 | 合成组合基准：程序化构造带植入真值的组合，零 API 依赖可重复 | B4 套件 |
| FR-7.5 | 基准**零第三方依赖**、一条命令跑全、指标口径写进 README、可证伪（注入缺陷必报未达标） | `bench` + 探活测试 |

### FR-8 桌面与 CLI 双形态（P1，M5）

| 编号 | 需求 | 验收方式 |
|---|---|---|
| FR-8.1 | 同一套引擎既有 CLI 也有桌面界面 | 同一输入 CLI 与 GUI 结论一致 |
| FR-8.2 | **界面只渲染引擎结果、零判定逻辑**；GUI 服务层是唯一引擎调用点 | AST 静态门禁三条齐上（不 import 规则层 + 无算术 BinOp + 无政策数值字面量） |
| FR-8.3 | 编排入口**上收**成引擎侧公开函数组，CLI/GUI 共用 | 三方对账测试（CLI stdout = 编排直调 = 报告章节） |

## 四、非功能需求（NFR）

| 编号 | 需求 | 判据 |
|---|---|---|
| NFR-1 **确定性** | 同一输入 + 同一规则包 → 逐字节一致的结果与报告 | 两轮生成 sha256 一致（实测背书，不是"应当"） |
| NFR-2 **计价精度** | 全链路 Decimal；金额两位小数 `ROUND_HALF_UP`；JSON 用 `parse_float=Decimal` | 1 分差异算例可被检出 |
| NFR-3 **零上传/离线** | 全本地处理，默认不联网，无任何外部调用 | 静态扫描源码无 HTTP 客户端调用（除文档 URL 常量） |
| NFR-4 **零 API 依赖** | 不使用 LLM；基准与全部结论可离线复现 | `grep` 无 LLM SDK 依赖；CI 断网可跑 |
| NFR-5 **零第三方依赖的核心层** | 核心计算层仅用 stdlib；可选件（XLSX/桌面）走 extras + 惰性导入 | core-only CI job 跑核心层守门测试通过 |
| NFR-6 **可核证** | 每条结论可追到规则条目；报告含参数来源块；脱敏审计可复跑 | 溯源完整性断言 + 审计脚本 |
| NFR-7 **健壮性** | 坏输入给原因码不崩；缺可选依赖给安装/发行包提示并降级 | 失败路径测试全覆盖 |
| NFR-8 **性能** | 千件组合排期 < 2 秒；基准全量单次 < 1 秒 | 计时门槛随 manifest 下发 |
| NFR-9 **跨平台可复现** | Windows/Linux 同结果；文本产物 LF；冻结产物位级一致 | EOL 守门 + 冻结再生成一致守门 |
| NFR-10 **解释器底线** | Python ≥ 3.12（3.8/3.9/3.10 均已 EOL；口径 2026-10-19 上抬，见 plan/06 D54） | CI 的 windows×3.12 与 ubuntu×3.12 作业通过 |

## 五、边界与非目标（守卫清单 —— 无对应 FR 一律不实现）

| # | 不做的事 | 判定 |
|---|---|---|
| G1 | 专利检索 / 价值评估 / 引证分析 | 属分析判断，缺确定性真值 |
| G2 | 缴费代办 / 对接官方缴费接口 / 对接 CNIPA 账户 | 越界且涉网 |
| G3 | 专利权有效性、侵权、权利要求分析 | 属法律判断 |
| G4 | 商标 / 著作权费用（首期仅专利） | 首期范围外，留扩展 |
| G5 | 判定"是否应当缴费/是否已失效"的**法律结论** | 只出费用测算与风险提示，不出法律意见 |
| G6 | 任何形式的数据外发（遥测/云同步/在线更新检查） | 合规红线 |
| G7 | 真实专利号 / 真实申请人 / 真实代理机构入库 | 数据纪律：一律合成 |

**免责声明为强制输出**：任何导出报告与 `calc` 人类可读输出末尾必须带免责段（"基于官方费率表与政策文本的费用测算，不构成法律或代理意见；正式缴费金额以国家知识产权局规定与缴费通知为准"）。

## 六、术语表

| 术语 | 含义 |
|---|---|
| 年度（annuity year） | 专利年费按**申请日起算的年度**计，第 N 年度区间如 1–3 年、4–6 年 |
| 缴费期限 | 每年度年费应在**上一年度期满前**缴纳（M1 已核：细则第 115 条，国务院令 769 号；补缴期 6 个月、滞纳金 5%/月，已随规则包入库） |
| 滞纳金 | 逾期缴费按每超期 1 个月加收当年**全额年费**的 5% |
| 费减 | 专利收费减缴，单主体减缴 85%、共同主体减缴 70%（财税〔2016〕78 号第四条） |
| 规则包 / ruleset | 按 `依据文件 × 版本` 组织的可执行 JSON 规则集 |
| 坐标（coordinate） | 规则包版本 + 适用锚点日期构成的定位串，随报告输出 |
| 门控（gate） | 计算前校验所引用规则条目 `status` 的检查；`pending` 拒绝进计算路径 |
| 作用域（scope） | 门控的分域单位：`calc`（年费阶梯）/`late`（滞纳金）/`reduction`（费减）/`check`（校核） |
